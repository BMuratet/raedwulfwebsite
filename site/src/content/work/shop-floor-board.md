At B10 Union, the shop foreman was the only person holding the full picture of every active job — which stage, who's on it, what's blocking it. Everyone else's answer to "what's next?" was "go ask him."

## The Constraint

Generic project-management tools didn't fit the shape of the shop. Monday.com was too rigid for how work actually moves through the stages; Notion was too abstract to answer "where is this job right now" at a glance; Miro was missing basic status fields entirely. The real problem wasn't a missing feature in an existing tool — it was that no existing tool matched the shop's actual stages and actual pace.

## What I Built

A purpose-built board, not a generic PM tool retrofitted to the shop: real shop stages — Incoming, Planning, Rough Mill, Build, Finish, Delivery — a Kanban view and a filtered list view, and a free-form status note per job so context doesn't get lost in a rigid schema. No accounts needed — anyone on the team can look at any device and see the truth.

## The Judgment Call

I scoped this deliberately small. It would have been easy to build toward "full project management system" — instead I built the smallest tool that actually closed the specific gap, one person as a single point of truth, and left clearly-labeled future work, Slack notifications, Notion sync, as a documented roadmap instead of half-building it now.

## What It Answered

Replaced the "ask the foreman" bottleneck with a board anyone can check in seconds. It's in daily use. What's still open is intentionally deferred, not missing by accident — the roadmap says so.
